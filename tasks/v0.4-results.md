## Native Figma check

File: [Website to Figma v0.4 native check](https://www.figma.com/design/xS4jsQjETMiSJp5VoVUZDv) (Newteam Drafts).

The exact paints, effects, borders and transforms that the renderer computes for an owned test page were applied through the Plugin API and compared side by side with the browser screenshot of the same capture. Figma accepted all of them without errors and matched the browser for: linear (side and angle), radial and conic gradients; inset plus drop shadow; layer blur; a positioned `::before` bar; 30° rotation (direction and centre); uppercase text case; text shadow; gradient-clipped text.

Difference found: Figma dashes were sparser than Chrome's. The renderer now uses a `[2w, w]` dash pattern; this tweak was **not re-checked natively** because of the call limit. A stray dash setting was applied to the conic test box in that file; it has no visible effect (the box has no stroke).

This check exercised the new paint code paths, not a full end-to-end import through the installed plugin. The full renderer bundle plus a scene is ~48 KB, at the MCP script limit.

## What changed

Speed
- Original JPEG/PNG/GIF bytes are kept; only other formats, EXIF-rotated or >4096 px images are re-encoded (JPEG when opaque, PNG when transparent).
- Font check sends only the font list; the editor fetches the scene without screenshots (`?screenshots=0`); the scene is validated once in the main thread.
- Native `figma.base64Decode`, fast UTF-8 SVG decoding, layout derivation cached per node, renderer yields to the event loop.
- Widths are captured in parallel pages of one browser.
- Shipped `code.js` dropped from 112 KB to 65 KB (no embedded UI copy, no test code).

Solidity
- Request and image-byte limits skip extra downloads instead of aborting the capture.
- Over-budget or deeply nested regions become measured images (`raster-fallback`) instead of failing.
- Pages that keep moving are frozen (animations finished or paused, timers, frames, idle callbacks and new animations stopped); the capture keeps a private timer.
- Media-frame screenshots run after the change check; screenshot-only drift is a warning, not a retry.
- Fixed: the last retry discarded its own image assets.
- Shipped build excludes verification hooks, telemetry and the Amazon special cases; `dist/diagnostic` keeps them for acceptance runs and `install-local --verify-*` installs that build.

Accuracy
- Gradients: linear, radial, conic, multiple layers, overlays above background photos, gradient text.
- Borders per side, dashed and dotted.
- Multiple and inset box shadows, text shadow, blur and backdrop blur.
- `::before`/`::after`: positioned boxes become layers; inline strings (labels, arrows, icon glyphs) join the text, including on inline descendants.
- Leaf layers keep CSS rotation natively.
- Text keeps authored characters and uses Figma text case.
- Variable names are readable (`color/#1a334d`, `space/10`); padding is bound once, so no unused variables.

## Still open

- Rotated containers keep measured child positions (issue reported).
- Repeating/sized gradients are drawn once across the box (issue reported).
- Different border colours per side use the widest side's colour (Figma has one stroke paint).
- Stripe single-width capture time (18 s).
- Full end-to-end native runs on 5 owned pages, and a 1,000-node import in the Desktop app.
- README still describes 0.3.0-alpha.5 and was not changed in this round.

## Side-by-side check against the live sites (20 November 2026)

Method: full-page Chrome screenshots of each site at 1440 and 390 were compared with exports of the imported Figma frames, plus a per-layer geometry check (Figma position and size against the measured browser box). The diagnostic build now exports every imported screen at source width for this.

| Difference found | Cause | Fix |
| --- | --- | --- |
| Header 12 px short, page 44 px short | Inline text boxes measured as the font's content area (30 px) instead of the line box (24 px) | Text bounds converted to line boxes |
| Collection tiles stretched across the row | Grid columns capped at the number of items (3 of 5 tracks) | All CSS tracks kept; cells placed from track geometry |
| Tile labels and gradients at the top | Absolute `inset-0` overlays hugged their content | Container-stretched boxes keep their height |
| Each grid 16 px short | Empty sentinel row still adds a CSS row gap | Measured gap kept as bottom padding |
| Cart icon drawn as a filled square | 512-unit SVG resized after import; strokes kept their weight | SVG imported at measured size with presentation attributes |
| Brand logos in colour | CSS `grayscale` ignored | Colour filters mapped to Figma image filters |
| "(TEST) Nike Air Jordan 5" reversed | Figma picks paragraph direction from the first strong letter | RLM mark for RTL copy that starts with Latin text |
| Mobile brand row shifted 16 px | Negative margins cannot overflow auto-layout padding | Padding shrinks for shared full-bleed edges |
| "View product" buttons shrank, FAQ rows 15 px taller | Hugging applied to block buttons; a large "+" run grew the line | Only shrink-wrapped boxes hug; taller runs keep the measured line |
| Sale badge text outside the badge | Badge label inherited `position: absolute` | Labels flow inside positioned boxes; badges hug and keep their right edge |
| All Puzzle Store mobile photos missing in one run | `networkidle` had resolved at load and did not wait for images requested by scrolling | Capture waits for every image to complete (30 s budget) |

Result after the fixes (geometry check, all layers): Superstarsy 1440 and 390 have no layer off by more than 1.5 px and identical page heights (2733 / 3195). Puzzle Store 1440 and 390 have identical page heights (9830 / 4599); the only remaining difference is 2–4 px in the two sale badges, because Figma's emoji glyphs are narrower than Chrome's. The hero carousel on Superstarsy shows whichever slide was active at capture. `npm run check`: 80 unit/API + 53 Chromium tests, 0 failures.

Final imports were placed on the "Superstarsy" and "Puzzle Store" pages with the normal (non-diagnostic) build; earlier imports moved to "Archive / first import". Diagnostic runs are on the page "Website capture verification".

Causes fixed in capture: consent banners that reload the page; image waits that either cut slow sites short or idled on lazy images outside the viewport; image bytes not kept (now fetched again through the egress proxy, redirects matched, `blob:` images read from the page, last resort a picture of what is painted); sprite icons (`<use>`); SVG files in `<img>` losing their style sheet; embedded players and canvases; widgets that build themselves after scrolling.

Causes fixed in the plugin: wrapped inline copy turned into one line; alignment, justification and edge padding now follow the measurement, and containers that fit no alignment keep measured positions; grid columns with unequal tracks; hug and fill applied only where they reproduce measured sizes; transparent gradient stops; one-line labels; component instances inheriting text sizing from the first member.

Native check so far: HubSpot went from 306 to 230 layers off (of 835) and Accenture from 89 to 52 (of 390, page height within 2 px) before the last rounds of fixes. Most remaining differences there come from fonts that are not installed (HubSpot Serif, Graphik, EYInterstate), which Figma substitutes.

A change made during this work froze a Figma tab: a text size was read while the screen was still being built. The check now runs once per screen after it is built; two EY imports then completed without freezing in a blank test file.

Not yet verified in Figma: the browser line count, component text sizing, and the image fixes above; a full re-import and comparison of all five sites with the final code. `npm run check`: 85 unit/API + 56 Chromium tests, 0 failures.

| Item | Result in Figma |

| Match with the site | unchanged: 1 of 312 and 1 of 284 layers off, page heights identical |
| Animations | hero and cards in their final state, as on the site |
| Sizing intent | the header's `flex: 1` item is Fill (1032 px, same picture); widening its row by 200 px gave the item 1232 px and kept the logo at the edge, as the page does. The stretched divider is Fill vertically |
| CSS variables | variables are named `color/primary`, `color/white`, `color/primary-700`, `color/gray-300`, `color/dark` … |
| Named, reused styles | 12 styles such as `superstarsy.com / Heading / 18 Regular` and `… / Label / 14 Medium`; the second import added 0 variables and 0 styles (30 and 12 before and after) |

Comparison images (site left, Figma right): `output/design-intent/superstarsy-1440-site-vs-figma-0.jpg`, `superstarsy-390-site-vs-figma-0.jpg` and `-1.jpg`.

Found by this check and fixed:

- A growing item in a `space-between` row stayed Fixed. Figma drops the gap of such a row once an item fills it, so the row now starts from the edge with the measured gap.
- The second import failed with Figma's "duplicate variable name": Figma stores numbers as 32-bit floats, so a stored value did not compare equal and the same name was created again. Stored values are now compared with a tolerance and a name is never created twice. The test double now refuses duplicate names and rounds like Figma.
- Chromium sometimes returned the reference screenshot as one 512 px tile repeated across the page (Superstarsy and Puzzle Store at 1440, 3 of about 20 captures, when other captures ran at the same time; not seen in 3 captures with the previous code, which is too few to say the new code causes it). The layers are not affected. The capture now recognises such a picture and retakes it, and reports `screenshot-unreliable` if it stays tiled. Recognition was tested on the real tiled pictures; the retake did not trigger in 6 later captures, so it has not been seen working live.

Not verified in Figma: the other four sites with the final code (their captures are unchanged; the simulated render is above), and the items on a site without CSS variables.

Tests on 26 November: 91 unit/API pass. Chromium: 53 of 59 pass; the 6 failures are all in `tests/browser/ui.test.ts`, where the installed Google Chrome exits at launch with `FATAL site_instance_impl.cc: Check failed: has_site_` before any project code runs.
